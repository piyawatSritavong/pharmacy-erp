### กฎที่ต้องรู้

- **สิทธิ์:** POS สมัครสมาชิกและแก้ข้อมูลติดต่อได้ (`customer.manage`) และรับชำระหนี้ได้ (`payment.collect`) แต่การให้วงเงินเครดิต ระดับราคาส่ง และการปรับแต้มต้องใช้ `customer.credit.manage` (super_admin, central_admin เท่านั้น) และการตั้งราคาส่งใช้ `price_tier.manage`
- **กันใช้ซ้ำเมื่อขายพร้อมกัน:** checkout ล็อกแถวลูกค้า (`FOR UPDATE`) ก่อนคิดแต้มและวงเงิน ทำให้หลายสาขาใช้แต้มก้อนเดียวกันหรือวงเงินเดียวกันพร้อมกันไม่ได้ และการรับชำระหนี้ก็ล็อกทั้งลูกค้าและบิล
- **สรุปสิ้นเดือน:** บิลขายเชื่อ (`sale_type='credit'`) ไม่เคยเป็น candidate ของการซ่อนหรือปรับราคา แม้จะรับชำระเป็นเงินสดภายหลัง ส่วนโค้ดการปิดรอบอื่นไม่ได้แตะ (ตามคำสั่งพัก month-end)
- **ลบบิลขายเชื่อที่รับเงินแล้วบางส่วนไม่ได้:** ต้องคืนเงินก่อน (สอดคล้องกับ decision #2)
- **ของแถมหมด:** ถ้าโปรให้ของแถมแต่สาขาไม่มีของ บิลยังขายได้ ระบบแถมเท่าที่มีและแจ้งที่ตะกร้า (เดิมทั้งบิลขายไม่ได้)

## ฐานข้อมูลและ API

Migration (additive ทั้งหมด):

- `073_quotation_keeps_discounts.sql` — ใบเสนอราคาเก็บส่วนลดท้ายบิลและส่วนลดของพนักงาน แปลงเป็นใบขายแล้วยอดเท่าเดิม
- `074_marketplace_providers.sql` — รายชื่อ Shopee/Lazada/TikTok Shop/LINE MyShop
- `075_customers_loyalty_credit_pricing.sql` — `customers`, `loyalty_point_entries`, `product_price_tiers`, คอลัมน์ลูกค้า/แต้ม/เครดิตบน `invoices`, `invoice_items.points_discount_share`, `invoice_payments.received_branch_id`, `parked_bills.customer_id`, `promotions.members_only`, ค่าตั้งต้นแต้ม และสิทธิ์ใหม่ 5 ตัว

API ใหม่: `GET/POST /customers`, `GET /customers/lookup`, `GET/PUT /customers/:id`, `POST /customers/:id/points`, `GET/PUT /loyalty-settings`, `GET /receivables`, `POST /receivables/payments`, `GET/PUT /products/:id/price-tiers`. Checkout, preview, invoice, quotation, parked bill และ remote cart รับ `customer_id` และ `redeem_points` เพิ่ม และ `payment_type` รับ `credit`

โค้ดหลัก: `backend/internal/modules/customers/`, `backend/internal/modules/sales/customer_sales.go`, `backend/internal/modules/sales/selling_tools.go` (tier price, member promotions, points), `backend/internal/modules/products/price_tiers.go`, `frontend/src/components/sections/{customer-console,receivables-console,pos-customer,product-pricing-dialog}.tsx`

## ข้อจำกัดที่ยังมี

- แต้มยังไม่มีวันหมดอายุ และยังไม่มีการรวมบัญชีลูกค้าที่ซ้ำกัน
- ขายเชื่อทั้งบิลเท่านั้น (ยังไม่มีจ่ายบางส่วนแล้วเชื่อส่วนที่เหลือ) และยังไม่มีผู้อนุมัติแยกเมื่อเกินวงเงิน ระบบปฏิเสธอย่างเดียว
- ลบบิลที่สมาชิกใช้แต้มที่ได้จากบิลนั้นไปแล้ว ระบบหักแต้มคืนได้เท่าที่เหลือ และบันทึกส่วนที่ขาดไว้ใน ledger
- อายุหนี้ใน demo จะเห็นแค่ "ยังไม่ถึงกำหนด" เพราะไม่ย้อนวันที่ของบิล (ห้ามแก้ created_at)
