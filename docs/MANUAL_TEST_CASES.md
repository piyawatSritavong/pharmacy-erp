## B. เพิ่มสินค้าและรูป

### B-01 เพิ่มหมวดสินค้า

1. Login ผู้ดูแลระบบ
2. เปิด **สินค้าและสต๊อก** → **สินค้าและหมวดหมู่** → **หมวดสินค้า**
3. กรอกชื่อ `หมวดทดสอบ Manual` และเลือกสี
4. กด **เพิ่มหมวด**

ผลที่คาดหวัง: แสดงข้อความ “เพิ่มหมวดสินค้าแล้ว” และหมวดใหม่อยู่ในรายการ/ตัวเลือกสินค้า

### B-02 เพิ่มสินค้า

1. เปิด tab **สินค้า**
2. กรอกข้อมูล:

| ช่อง | ค่า |
|---|---|
| SKU | `MANUAL-001` |
| บาร์โค้ด | `885000000001` |
| ชื่อสินค้า | `สินค้าทดสอบ Manual` |
| หมวด | `หมวดทดสอบ Manual` |
| ราคาทุน | `40` |
| ราคาสด | `60` |
| ราคาปลีก | `65` |
| ราคาผ่อน | `70` |
| หน่วยนับ | `ชิ้น` |

3. ตรวจว่า SKU ถูกสร้างเป็น `PRD-YYYYMMDD-XXXXXX` แล้วแก้เป็น `MANUAL-001`
4. เลือกรูป JPEG/PNG/WebP ที่มีขนาดไม่เกิน 5 MB
5. กด **เพิ่มสินค้า**

ผลที่คาดหวัง: สินค้าถูกสร้าง รายการแสดงในแถบซ้าย เลือกแล้วเห็นรายละเอียดด้านขวา และค้นหาด้วยชื่อ/SKU/บาร์โค้ดได้

### B-04 รายการสินค้าขนาดใหญ่

1. ค้นหาชื่อหรือ SKU จากช่องด้านซ้าย
2. กรองหมวดและสถานะ
3. กดหน้าถัดไป/ก่อนหน้า

ผลที่คาดหวัง: backend ส่งครั้งละ 50 รายการ แสดงจำนวนรวม/เลขหน้า และไม่ render ฟอร์มสินค้าทั้งหมดพร้อมกัน

### B-03 แก้ไขสินค้าและรูป

1. เปลี่ยนรายละเอียดหรือราคา
2. เลือกรูปใหม่
3. กด **บันทึกสินค้า**
4. restart frontend/backend container แล้วกลับมาเปิดหน้าเดิม

ผลที่คาดหวัง: ข้อมูลและรูปใหม่ยังอยู่ แสดงว่าฐานข้อมูลและ upload volume ทำงาน

## C. สต๊อกจริงและสต๊อกผี

### C-01 หน้า Ghost เป็น read-only และเลือกแหล่งข้อมูลอัตโนมัติ

1. Login ด้วย Superadmin แล้วเปิด **สต๊อกผี**
2. ตรวจรายการสินค้า รายละเอียด ประวัติ และเปิด **ดู Lot/วันหมดอายุ**
3. เปิด URL เดิมพร้อม query `?inventory_branch=<uuid อื่น>`

ผลที่คาดหวัง: ยอดและ Lot มาจาก active WH เดิมเสมอ ไม่มี dropdown หรือข้อความสาขา/โกดัง และไม่มีราคา ส่วนลด จุดเตือน ปุ่มตั้งค่า ปรับยอด ลบสินค้า หรืออัปโหลดรูป

### C-02 Ghost เปลี่ยนผ่าน PO และ Month-End เท่านั้น

1. สร้างและ post ใบสั่งซื้อเข้าที่ WH โดยมีรายการ Ghost
2. ตรวจว่ายอด, Lot, movement และ movement-lot link เพิ่มตรงกัน
3. รัน Month-End ที่มีบิลเข้าเงื่อนไข แล้วตรวจ Ghost deduction/deficit
4. ทดลองส่ง Ghost ไปยัง API adjust, receive, rebalance, receipt approval, sale, quotation, transfer และ return

ผลที่คาดหวัง: PO และ Month-End สำเร็จ; API อื่นตอบ `400` สำหรับ Superadmin พร้อมข้อความให้ใช้ PO หรือ Month-End และตอบ `403` สำหรับ role อื่น โดย Real request เดิมยังทำงานปกติ

### C-03 ปรับยอดและป้องกันยอดติดลบ

1. เปิด **สต๊อกจริง** และเลือก **ปรับยอดด้วยตนเอง**
2. กรอก `-1` แล้วบันทึก
3. กรอก `-9999` แล้วบันทึกอีกครั้ง

ผลที่คาดหวัง: ครั้งแรกยอดจริงลดเหลือ 7 ครั้งที่สองถูกปฏิเสธและยอดไม่ติดลบ

### C-04 POS ส่งคำขอรับสินค้าและตรวจ conflict

1. Login บัญชีพนักงานขาย เปิด **เช็กสต๊อก**
2. ตรวจว่าตารางมีเฉพาะคอลัมน์สต๊อกจริงและไม่มีข้อความสต๊อกผี
3. เลือกสินค้า กรอกจำนวน `3` และหมายเหตุ แล้วกด **ส่งให้ผู้ดูแลตรวจสอบ**
4. Login ผู้ดูแลในอีก browser แล้วปรับยอดสินค้ารายการเดียวกัน `+1`
5. เปิด **สินค้าและการโอน** → **คำขอรับสินค้า**

ผลที่คาดหวัง: มีการแจ้งเตือนบนแดชบอร์ด คำขอแสดงป้าย **พบ conflict** และเทียบยอดตอนแจ้งกับยอดปัจจุบันครบ

### C-05 อนุมัติหรือไม่รับนำเข้า

1. ในคำขอ pending ปรับจำนวนที่อนุมัติ
2. ระบุจำนวนอนุมัติเข้าสต๊อกจริง
3. กด **ยืนยันนำเข้า** และตรวจยอด/ประวัติ movement
4. ส่งคำขอใหม่จาก POS แล้วกด **ไม่รับนำเข้า**

ผลที่คาดหวัง: คำขอแรกเพิ่มสต๊อกจริงเพียงครั้งเดียว ส่วนคำขอที่ปฏิเสธไม่เปลี่ยนสต๊อก และการแก้ request เป็น Ghost ถูกปฏิเสธ

## D. POS

### D-01 ขายจากสต๊อกจริงด้วยเงินสด

1. Login บัญชีพนักงานขาย
2. ค้นหา `MANUAL-001` หรือสแกน/กรอกบาร์โค้ด
3. คลิกสินค้าเพื่อเพิ่มลงตะกร้า
4. กด **รับชำระเงิน**
5. กรอกยอดรับมากกว่ายอดรวม แล้วกดคำนวณเงินทอน
6. กด **ยืนยันการชำระเงิน**

ผลที่คาดหวัง: ออกใบเสร็จสำเร็จ เงินทอนถูกต้อง สต๊อกจริงลด 1 และสต๊อกผีไม่เปลี่ยน

### D-02 ขายด้วยเงินโอน

1. เพิ่มสินค้าเดิมลงตะกร้า
2. เลือกช่องทาง **เงินโอน** และกรอกเลขอ้างอิง
3. ยืนยันชำระเงิน

ผลที่คาดหวัง: ออกใบเสร็จสำเร็จ สต๊อกจริงลด 1 และรายการชำระแสดงเป็นเงินโอน

### D-02A ขายด้วยเงินสดผสมเงินโอน

1. เพิ่มสินค้าลงตะกร้าและเลือก **เงินสด + เงินโอน**
2. กรอกยอดโอน เลขอ้างอิง และเงินสดที่รับมากกว่ายอดเงินสดสุทธิ
3. ตรวจยอดเงินสด/เงินโอน/เงินทอน แล้วกดยืนยัน

ผลที่คาดหวัง: ออกใบเสร็จหนึ่งใบ มีรายการชำระเงินสดและเงินโอนอย่างละหนึ่งบรรทัด ผลรวมตรงยอดใบขาย เงินทอนถูกต้อง และสต๊อกจริงลดเพียงครั้งเดียว

### D-03 ป้องกันขายเกินสต๊อก

1. เพิ่มสินค้าจนจำนวนมากกว่าสต๊อกจริง
2. กดรับชำระ

ผลที่คาดหวัง: backend ปฏิเสธพร้อมข้อความสต๊อกไม่เพียงพอ ไม่มี invoice/payment ใหม่ และยอดสต๊อกไม่เปลี่ยน

### D-04 Layout และประวัติ

1. เปิด POS ที่ 1440×900
2. ตรวจว่า grid แสดง 3 คอลัมน์และหน้าไม่เลื่อนทั้งหน้า โดยพื้นที่สินค้าเลื่อนได้
3. เปิดเมนู **ประวัติ**
4. เปิดใบเสร็จย้อนหลัง

ผลที่คาดหวัง: ตะกร้าคงที่, ไม่มีส่วน “รายการขายล่าสุด” ใต้ POS และใบเสร็จย้อนหลังเปิดได้จากเมนูประวัติ
